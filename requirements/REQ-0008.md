# REQ-0008

- 创建日期：2026-09-20
- 分支：`req-0008-pi-086`

## 描述

适配 Pi 0.86.0：把仓库开发基准依赖升级到 0.86.0，修复 context-management 在 Compactor Request 中丢失 system prompt 的问题（Provider.streamSimple 现在要求 normcontext化的 TranscriptContext）与 prune 中已失效的 addedToolNames 字段，并按 0.86.0 的运行行为对全部 extension 做一次适配性扫描。

## 已确认设计

- 开发基准依赖升到 0.86.0，只更新根 `package-lock.json`：仓库按 AGENTS.md 只声明 `peerDependencies: "*"`，不在 `package.json` 增加 pi 包声明。
- Compactor Request 改走 `ctx.modelRegistry.streamSimple()`，不再自建 `provider` 通道：0.86.0 的 `Provider.streamSimple` 只接受 `normalizeContext()` 产出的 `TranscriptContext`，而 registry 接收裸 `Context`，并负责 transcript 归一化、凭据解析与 `auth.baseUrl` 覆盖。`ModelsError` 的 `auth`/`oauth`/`provider` 映射回 `context_management.compactor_auth_failure`，其余仍归入 `compactor_transport_failure`。
- `prune` 停止保留 `addedToolNames`：0.86.0 已从 toolResult 移除该字段，工具声明改由 system 消息的 `toolsAdded`/`toolsRemoved` 承载。
- 新增 `checkpointPrefix()` 识别 checkpoint 前缀：跳过前导 system 消息后再判断 `compactionSummary`。0.86.0 把 `systemMessage` 写进 compaction entry 并按 `[systemMessage, summary]` 回放，原有「摘要固定在 `messages[0]`」的假设会让 offset 退化为 0，既把 system 消息与旧摘要算作新可压缩内容，也让 ADR-0015 的滚动合并静默失效。
- pending checkpoint 投影保留解析后的 system 消息，并写入合成 compaction entry 的 `systemMessage`：与安装后的回放形状 `[systemMessage, summary, ...kept]` 一致，使 entry↔message 映射不错位。0.86.0 的 prompt 由 messages 推导（`getCurrentSystemPrompt(messages)`），投影丢掉它会让该窗口的请求没有 system prompt。

## 扫描结论（全部 extension 对照 0.86.0 行为）

- 需要适配的只有 context-management（注册了 `context` 钩子、直连 provider、读写 compaction/session entry）：上述四处已处理。
- sub-agent：child provider 只透传 runtime 传入的 context，`getProvider`/`getProviderAuth`/`getApiKeyAndHeaders`/`find` 在 0.86.0 仍存在，无需改动。
- memory：`before_agent_start` 注入 custom message（非 `systemPrompt`），不受 0.86.0 的 system prompt 修复影响。
- plan：`before_agent_start` 只做副作用且返回 `undefined`，无需改动。
- eureka-ui：覆盖内置工具定义时先展开 `source.metadata` 并显式保留 `constrainedSampling`，已兼容 0.86.0 的 strict-prefer JSON-schema sampling。
- goal / todo / progress-widget / tavily-web-search：只读 session entry、渲染或与 0.86.0 变更点无接触，无需改动。
- 横切项：仓库无 `user_bash` 使用；无 `addedToolNames` 残留；所有注册工具都带 `parameters`（0.86.0 会拒绝无 schema 的工具）；事件处理器全部静态注册，不受「dispatch 中增删只对后续生效」影响。

- prompt cache warming（0.86.0 新增，`cacheWarming` 默认 `"streaming"`）：Pi 在上下文变化时（含 compaction）主动停止 warming，与我们的 checkpoint 安装无冲突；且 warming 需要模型带 `promptCache` 生命周期元数据，当前所用 provider（deepseek / opencode-go / kimi-coding / openai-codex）均无该元数据，实际不会触发。结论已记入 context-management README 的限制小节。
