# REQ-0005

- 创建日期：2026-09-01
- 分支：`req-0005-plan-optimization`

## 描述

优化现有 Plan 工作流，修复使用中暴露的问题并改进交互与状态管理。

## 已确认问题

### 1. 审核界面脱离正常内容流

当前审核使用终端中央的覆盖式弹窗，视觉上与正文缺少清晰层次，同时遮挡会话内容，整体体验突兀。

Proposal 与审核提示必须出现在正常 transcript 的最新内容位置，像普通输出一样参与内容流，而不是覆盖在终端中央。Proposal 即使在 transcript 详情折叠状态下也完整显示 objective、overview、Steps、替换 Todo 警告及决策命令；不再自动打开 overlay、selector、editor 或其他模态 UI。Approve、Revise、Cancel 只接受用户显式执行 `/plan approve`、`/plan revise [feedback]`、`/plan cancel`。

### 2. Plan 状态位于 footer，位置及呈现方式不统一

当前 Plan 通过 footer 在输入框下方显示 drafting、reviewing、handoff pending 等状态，位置不符合主要进度信息的阅读顺序，也与仓库已有的统一进度组件割裂。

移除 Plan 独立 footer，把 Plan 作为 `progress-widget` 的状态来源，由统一 Progress Widget 在输入框上方展示，并与 Goal、Todo、Sub-agent 的进度信息保持一致。组件从上到下的固定顺序为：`Subagents → Plan → Todos → Goal → 输入框`。Plan 在 Compact 与 Full View 中均使用一行，保留 phase、Plan ID、可用 revision 及 Workspace Mutation 封锁提示；`progress-widget` 缺席或释放投影时，Plan 使用同样内容的输入框上方 fallback widget。

## 验收标准

- TUI 提交 Proposal 后，完整审核内容进入 transcript，且 `agent_end` 不打开任何覆盖层或阻塞式审核 UI。
- 未收到用户显式 `/plan` 决策前，状态保持 `reviewing`，不发生批准、修订或取消。
- Plan 不再调用 `setStatus`；活动状态只投影到输入框上方的 fallback 或组合 Progress Widget。
- 组合 Progress Widget 在 Compact 与 Full View 中都按 `Subagents → Plan → Todos → Goal` 排列，并在 Plan inactive 后移除 Plan 区段。
- TUI、RPC、JSON、print 均安全加载；缺失或失效的组合 widget 不影响 Plan 状态机和门禁。
